# 24 张卡面识别模板：本地重建实验

本目录的 `rebuild_card_templates.py` 和 `card-template-spec.json` 不包含游戏图片或本机源路径。它们只覆盖已找到原始参考结果的 24 张 `board_art` 模板；不能恢复整套游戏素材，也不是完整安装方案。另有 5 条原来源记录无对应参考输出，没有生成。

## 前置条件

在 Windows 上准备 Python 和 Pillow。开发时使用原项目运行环境的 Python 3.14 和 Pillow 12.3.0；未测试其他版本。自行从有权使用的来源准备与清单中 `source_sha256` 一致的原始卡面图片，并按清单 `input_file` 重命名，放在同一个输入目录。脚本不会下载图片或规避任何限制，图片字节不同时会停止输出。来源和使用权限由使用者确认。

在脚本与清单所在目录中，替换以下占位符为自己新建或空的目录：

```powershell
python -B .\rebuild_card_templates.py --sources "<自行准备的卡面目录>" --output "<新建或空的输出目录>"
```

脚本验证 24 张输入的 SHA-256，并按原记录裁剪框 `(70, 145, 481, 554)` 截取、RGB 转换、以 BICUBIC 缩放到 122×121；每张输出的 RGB 像素哈希必须与原模板相同才写入。它不会覆盖已有输出文件夹中的文件。PNG 编码字节可能不同；验证针对像素，不代表文件本身哈希相同。

## 已验证与未验证

已使用本机记录的源图在工作区临时目录端到端执行：24 张输出均与原模板逐像素一致，临时图像已删除；未启动游戏或自动化。没有验证联网获取源图、其他 Pillow 版本、全部识别场景或面板运行。

其他卡面、场景、界面、数字和棋盘模板仍缺完整采集与校准流程。场景的 22 个参考图及 ROI 只能作为人工逐项重建的线索：需要用户自己获得相应的 1280×720 画面、逐项核对参考文件和 ROI，并在隔离环境验证识别；尚无完整工具或实测步骤。只有在权利、隐私和行为验证完成后，才能决定是否将生成的素材用于公开分发或安装。
